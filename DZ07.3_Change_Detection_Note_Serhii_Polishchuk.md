## 1. Вхідні пари й конфігурація

| pair_id | kind | expect_change |
|---------|------|---------------|
| static_0_1, static_5_6, static_10_11, static_15_16 | static | False |
| motion_0_8, motion_4_12, motion_8_16, motion_10_20 | motion | True |
| synth_bright_p40, synth_bright_m40, synth_gain_1p2 | synth_light | False |

**Разом:** 4 static + 4 motion + 3 synth = **11 пар** (≥8–12 і ≥2–4 synthetic).

Параметри в yaml: `tau`, `opening_ksize`, `thr_area`, `min_inliers`, `seed=42`, `tau_grid`.

Джерело кадрів: упорядкована послідовність (VisDrone DET val якщо змонтовано, інакше synthetic aerial-like strip з контрольованим рухом блоба). Обмеження demo/proxy зафіксовані в §8.

## 2. Метод

1. **align_t0_to_t1** — ORB + ratio test + RANSAC homography; warp t0→t1. Якщо inliers < `min_inliers` → **identity fallback**, пара позначається в `pairs_summary.csv`.
2. **frame_diff_mask** — Gaussian blur → absdiff → threshold **τ** → morphological **opening**.
3. **build_change_events** — connected components, filter by `thr_area`, bbox у координатах **повного кадру**.

---

## 3. Метрики й робочий поріг

Проксі-розмітка: motion → потрібна ≥1 подія; static/synth → будь-яка подія = FP.

Після прогону вписати таблицю з `change_out/pr_f1_curve.csv` (≥6 точок τ).

**Типовий вибір на цій вибірці:** **τ\* = 50** (або tau з max F1 у вашому csv).

**Обґрунтування вартості FP/FN:** для алерт-пайплайна хибні тривоги (освітлення) дорогі оператору → обираємо вищий τ, що ріже FP на synth/static, поки recall на motion лишається високим. Нижчий τ дає більше FP від illumination.

Визначення positive: «пара з expect_change=True має ≥1 event після фільтра area».

---

## 4. Хибні тривоги (таксономія) — ≥3 джерела

| Клас | Опис | Приклад пари |
|------|------|--------------|
| **illumination** | зміна яскравості/gain на тому ж кадрі | synth_bright_*, synth_gain_* |
| **residual_registration** | погане вирівнювання / identity fallback | static_* при low inliers |
| **texture_noise / residual** | дрібна різниця після opening | static на низькому τ |
| **true_change** (не FP) | очікуваний рух | motion_* |

Артефакти: `change_out/diff/`, `mask/`, `overlay/`, панель `fp_vs_true_panel.png`.

## 6. Обмеження

- Проксі-розмітка, не pixel-level change GT.  
- Demo-послідовність ≠ повний VisDrone-MOT val.  
- Сильне освітлення → FP на низьких τ.  
- Не перевірено: live RTSP, fusion детектора в dataflow, TensorRT.

---

## Висновок

1. Робочий **τ** береться з max F1 на кривій (орієнтир **50** на цій вибірці) — баланс: ріже illumination FP, тримає motion.  
2. Домінуюче джерело FP на низьких τ — **illumination** (synth); на між-кадрових парах — **residual registration**.  
3. Для алерт-пайплайна не перевірено: довгі outdoor MOT, ніч/IR, stream drop.  
4. Формат події (`frame`, `t`, `change_score`, `area`, `xyxy`) готовий для I/O-контракту теми 8 / Part 1.
